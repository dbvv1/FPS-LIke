# FPS-Like 设计任务书

**历史启动顺序**：MOBA-Like main 可玩后开工，首轮先做模拟层和无画面验收；当前已进入持续改进，独立的核心、成套美术与其他案例并行，不再把旧启动顺序当串行等待条件。设计变化直接改本文件；进度和阻塞写在 a1dbv TASKS。

## 目标

从单个爆破点起步，分阶段扩成离线 5v5 爆破攻防：进攻方安放炸弹或全歼对手，防守方拆弹或守住时间。品质重点有三项：瞄准跟手、开枪有分量（后坐、声音、命中反馈）、机器人看不到就不开枪，靠声音和线索找人。

首要目的不是另造足够创新的玩法，而是把 a1dbv 的知识、资产制作、实现、测试与质量评估串成全链路 AI 游戏开发案例，并构建可复用的核心客户端模块。战术射击以 CS2 的移动／停步、射击、掩体、经济与爆破决策为主干，结合 Valorant 式技能创造信息与空间选择；美术以 Valorant 的风格化角色／场景和战斗可读性为主。原创或许可清楚的资产是版权边界，不是要求重新发明成熟交互。

## 视觉与技能方向：风格化战术射击

[Valorant 官方着色与玩法清晰度说明](https://www.riotgames.com/en/news/valorant-shaders-and-gameplay-clarity)用于场景简化、角色轮廓、材质／明暗分层和视觉焦点的风格参照，不代表已实际游玩或达到其质量，也不据“风格化”断言制作一定更容易。枪械、手部动作、角色、完整场景、特效、音频与 HUD 成套统一；不搬用 Riot／Valve 的商业角色模型、专属图标、品牌或地图资产；可参照成熟 UI 的信息层级与交互，也可实现通用烟幕／侦察机制，不以资产边界阻止成熟玩法。

技能首批限少量代表性烟幕与侦察，在同一个回合规则下明确费用／次数、施放与打断、持续时间、敌我可见性及反制。先写一致的移动精度、后坐／恢复、经济与技能资源规则，再实现；不将两作互相矛盾的规则机械拼接。烟幕必须作用于真实信息与视线判定，而不是只有粒子；侦察须说明何时揭示、揭示给谁、何时过期，不能把全局状态直接暴露给玩家或机器人。机器人须能理解烟幕遮挡、侦察线索的可信范围与失效、改道／等待／回防，不能沿用无技能时的全信息逻辑冒称适配。先交可玩小规模技能验证，再纳入离线 5v5；这是新增玩法范围，须用实际实现、资源与机器人适配成本重新校准工程量，不沿用无技能版本估时。当前只确定方向，不宣称技能已存在或已验证。

## 射击循环的品质参照

主品质参照为 [Counter-Strike 2 官方入口](https://www.counter-strike.net/cs2)（[Valve 的 Steam 页面](https://store.steampowered.com/app/730/CounterStrike_2/)）：取小场景内一次步枪“移动／停止→瞄准→开火→命中或落空→恢复→换弹”比较，阶段 A 不扩整套地图枪库、经济、联网或反作弊；离线 5v5、基础经济与代表性武器／投掷物按下列 B/C 阶段推进。[Krunker](https://krunker.io/) 只保留作辅助网页 FPS 对照，不能替代 CS2 标准。武器、角色、地图、美术、声音和品牌内容不复制参照资产。

- **画面与动画**：枪体和双手有清楚的前后关系；每发有短促推动和连续复位；弹匣退出、装入、闭锁可读，不能用整枪倾斜定格代替整个换弹。
- **瞄准与反馈**：中心瞄点跟随输入，枪体动画不偷偷改变弹道；开枪、命中、要害与击倒可区分，未命中不制造命中提示。
- **声音**：开火、枪械机构、换弹阶段与命中确认分层，近远和左右可辨；声音与现有玩法事件同步，不泄露未授权敌人信息。
- **界面与完成度**：弹药、换弹剩余时间和重新就绪可迅速读取；切枪、暂停、回合结束不能留下假枪口火光或重复播放旧事件。

CS2 对照必须逐项记录，而不是凭印象填数：移动与停步后的射击精度、连续开火与停止后的后坐恢复、命中与死亡的可读性、换弹阶段及打断、枪声／机构／脚步的层次与同步、界面对战场信息的遮挡。记录参照实际版本、输入和截图／录像；本作相应模块能复用的契约与工具链一并说明。没有实际玩过或听到的维度保持未验证，不自行把当前实现写成 CS2 已有行为。

同一视角和输入片段做原版／候选对照，另与参照并排截图或录像；实际玩后由非作者按上述维度列差距并复评。自动测试是回归门槛，不能据此宣布品质完成。CPU 回退和 Three.js 分开记录；参照或 GPU 无法实玩时，该项保持未验证，不降低目标。

## 起步版本范围（保留历史设计）

- **地图**：一张小图，一个炸弹点，三条进攻路线，包含近距离拐角和中距离对枪位。
- **武器**：一把步枪、一把手枪，有弹匣、换弹、固定后坐图案和移动射击惩罚。
- **对局**：1v1 起步，模拟层按 3v3 设计；回合计时、安放与拆除、胜负与换边。
- **操作**：鼠标锁定视角，WASD 移动，蹲伏、静步、换弹、切枪。暂停菜单提供 0.10–3.00× 鼠标倍率；1.00× 保持原版，草稿按应用保存到当前浏览器，取消不生效，恢复默认清除保存覆盖。设置不改弹道、后坐或已经记录的命令。菜单打开时 Tab／Shift+Tab 不进入背景对局控件；退出指针锁暂停后，焦点交给继续按钮。设置内 Esc 取消未应用草稿并返回设置入口；暂停菜单上的 Esc 不自动恢复游戏，继续仍由按钮确认。

### 首轮规则

回合 70 秒，安放 3 秒、拆除 5 秒、引爆 25 秒；连续 3 回合后换边，比分跟随队伍而非攻守身份。移动、开枪、换弹或切枪会打断安放／拆除，松开交互键也会清空进度。炸弹未安放时，进攻方全灭由防守方获胜；安放后即使进攻方全灭，仍须拆除或等待引爆。双方角色都会挡子弹，友伤开启。

同一时刻先完成已到期的交互，再处理引爆／回合超时；因此刚好完成的拆除优先于爆炸。开枪事件按帧内时刻排序，相同时刻按命令在输入批次中的顺序执行。

### 旁置完整训练赛候选

`?match=complete-v1` 在现有 1v1 爆破规则上提供六回合训练赛：前三回合进攻、后三回合防守，每侧恰好三回合；打满六回合后结算总比分，3:3 明确为平局，不加未经设计的突然死亡。六回合是本候选对“每三回合换边”的完整会话编排，不改变默认无限回合训练，也不改模拟规则、武器伤害、机器人难度、地图或经济。

菜单给出当前攻守职责，第三回合后说明下一回合交换身份；每回合记录攻守、胜负及胜负原因，整场结算展示本人射击命中与目标获胜次数。结束后的“再打一场”重置比分、记录和对局状态，回到部署确认，不自动锁鼠标开战。只统计本人的既有射击事实，不显示隐藏敌人的位置。该候选的浏览器、实际可读性与完整游玩验收独立进行。

## 技术默认

- **TypeScript + Vite，Three.js 渲染**；物理与角色控制用 [Rapier](https://github.com/dimforge/rapier.js) 的角色控制器和射线检测；机器人寻路用 [recast-navigation-js](https://github.com/isaac-mason/recast-navigation-js)。
- 无 WebGL2 时提供明确标识的 Canvas2D CPU 第一人称回退，读取同一地图与模拟快照；简化画面与输入单列验证，不代替 Three.js / WebGL2 验收。
- **模拟**：60 Hz 固定逻辑帧，只接受输入命令，按“种子 + 命令序列”可复现。开枪命令带帧内时间和当时的视角，命中按开枪那一刻判定，不按下一个逻辑帧。
- **瞄准**：视角在每个渲染帧直接应用累计的鼠标位移，不等逻辑帧；指针锁定时请求 `unadjustedMovement`，绕过系统鼠标加速，浏览器不支持时回退普通锁定。
- **机器人**：只对有视线的目标开火；难度靠反应时间、预瞄误差和压枪能力区分，不靠穿墙信息或伤害加成。
- 换掉任何一项，在本节写一句理由。

## 自动验收目标

`npm run sim -- --games 200 --seed 1` 应满足：

- 0 异常，0 卡死，0 次对无视线目标开火；
- 同难度机器人按攻守统计：多个种子跑满 500 局以上，进攻方胜率在 40%–60%，用来检查地图攻守平衡；
- 高难度对低难度胜率不低于 80%，反应时间分布符合难度配置；
- 同一种子下后坐图案和重放状态哈希一致；
- 输出各武器命中率、爆头率和击杀时间，作为数值修改前后的对照。

瞄准跟手程度、后坐手感、脚步方向能不能听准，进入 a1dbv TASKS“待人工验收”。

## 里程碑（先离线，逐段交付）

- **已有基础与历史证据**：网页 1v1 与现有步枪／手枪沿用前文证据和未验证项；可配置多实体不等于客户端已具备 5v5 战术对局。
- **A：一次完整核心交战与爆破回合**。小场景内完成移动／停步、瞄准、开火／后坐恢复、命中或落空、换弹／打断、切枪、掩体与听声，以及安放／拆除／回合结算；同轮交枪与手部动作、敌人轮廓、完整场景、特效、声音和 HUD。按 CS2 对应操作维度对照，不用整枪倾斜代替换弹、不用菜单完整代替枪感。
- **B：离线 5v5 完整比赛**。1 名玩家与 9 名机器人，在一张原创双点小图完成攻守、基础购买／装备、有限武器／投掷物及上述首批烟幕／侦察技能、换边、整场结算和重开。机器人具有分路、进攻／守点、携弹／安放、拆弹与回防职责；逐步交付可试玩子轮，验证多个种子不死锁、职责有效、感知不作弊，十个会开枪的实体不算完成战术团队对局。
- **C：核心操作和内容扩展**。逐批补代表性武器类别、投掷物、技能组合与反制、经济选择、地图交战空间和机器人配合；每批同步对应武器／角色动作、材质、音效、特效和说明，记清参照版本与已测／未测差距。第二次武器／路线修改继续回填模块兼容证据；小枪库是阶段交付，不表示 CS2 所有核心操作及内容已实现，也不复制商业地图和资产。

历史第二次需求修改的范围、资源返工与回放／数据兼容继续按 [05 §11](https://github.com/dbvv1/a1dbv/blob/main/domains/game-dev/05-gameplay-architecture.md#11-给-ai-第二次修改的最小契约) 留证；本次路线修订不覆盖既有实现记录。

每阶段都交可直接试玩的完整体验，而不是只交菜单、接口或测试报告；核心玩法与成套场景、角色／物件、动画、特效、声音、HUD 同步推进。AI 生成、自制与许可清楚的现成资源均可采用，须记录来源／生成配方、可编辑源和一次接入后二改；不直接使用商业参照资产。验收保留固定构建、正常游玩片段、同机位同状态前后证据和非作者判断；测试、无画面断言与无头 smoke 是合入门槛，不替代感知验收。画面／手感更换默认仍遵守既有 GPU 对照／输入回放与逐帧反馈证据门槛，未看、未听、未玩照实标注。阶段是后续工作目标，不把下列清单当已实现；首两轮实际可玩交付后再校准工程量，不承诺日期。

### 联机接缝（设计约束，不是已实现功能）

本阶段不实现联网；后续联机目标保留，当前不建房间、匹配、账号服务、同步框架、预测回滚或反作弊。玩家与机器人经同一输入命令边界驱动单一权威模拟，命令约定稳定实体 ID、序号与逻辑 tick；模拟状态和表现分离，表现消费快照与可去重事件，重开清理生命周期。种子、初始状态、内容版本及命令记录应能解释一次对局，明确可序列化状态边界与时间来源，避免把 DOM、渲染对象或本机存档直接当权威状态。已有部分复用，缺项随当前功能补齐并逐项验证，不为“以后联网”先造整套框架。

未来联机先评估服务端权威方案；本地同版本重放一致不等于跨浏览器确定性，也不预先承诺帧同步可用。实际网络同步、延迟、断线与安全验收另立阶段，未测试项不记为联机就绪。

## 当前阶段不实现

联网对战、匹配排位、皮肤、反作弊；后续联机目标保留，不用网络框架前置阻塞离线玩法与美术。

## 旁置离线小队基础候选

`?squads=offline-v1&match=complete-v1&environment=courtyard-v1` 将同一个客户端切为 1 玩家与 9 机器人，沿用六回合、第三回合后换边、比分结算和再开；单独 `squads=offline-v1` 可使用原无限回合。缺省仍是原 1v1；未知或重复候选参数报错，不静默切换。HUD 标出离线 5v5、双方存活人数和本人／队友携带信标。

`GameOptions.formation='squads-v1'` 显式记录阵型版本，随候选状态哈希参与回放；只有该选项将容量放宽为每队最多 5，旧缺省每队最多 3、旧出生与回放哈希不变。新阵型在每次开局／换边从原地图西侧掩体两端部署，不更换地图几何或离线导航。固定实体 ID 与各自种子分别驱动九个 Bot；玩家与机器人仍经同一个 `Game.step(commands)`，没有添加联网服务或同步框架。

机器人仅消费自身合法观察与明确的同队生命／位置通讯，不读取隐藏敌人位置。分路阶段单调前进；携弹者推进安放，掉落时唯一就近机器人回收；植弹后唯一就近防守机器人拆除，其余使用不同掩护点，负责者死亡后重新选择。交火仍以可见敌人为前提；该基础没有承诺复杂包夹、避让或竞技策略。单点地图仍容易较快全歼，不代表阶段 B 的双点、经济、技能与完整团队策略已经完成。
