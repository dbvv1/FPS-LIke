# FPS-Like 设计任务书

**启动顺序**：MOBA-Like main 可玩后开工，首轮先做模拟层和无画面验收。设计变化直接改本文件；进度和阻塞写在 a1dbv TASKS。

## 目标

单个爆破点的回合制攻防：进攻方安放炸弹或全歼对手，防守方拆弹或守住时间。品质重点有三项：瞄准跟手、开枪有分量（后坐、声音、命中反馈）、机器人看不到就不开枪，靠声音和线索找人。

首要目的不是另造足够创新的玩法，而是把 a1dbv 的知识、资产制作、实现、测试与质量评估串成全链路 AI 游戏开发案例，并构建可复用的核心客户端模块。玩法和体验尽可能参照 CS2；原创或许可清楚的资产是版权边界，不是要求重新发明成熟交互。

## 射击循环的品质参照

主品质参照为 [Counter-Strike 2 官方入口](https://www.counter-strike.net/cs2)（[Valve 的 Steam 页面](https://store.steampowered.com/app/730/CounterStrike_2/)）：取小场景内一次步枪“移动／停止→瞄准→开火→命中或落空→恢复→换弹”比较，不扩展为完整地图枪库、经济、联网或反作弊复刻。[Krunker](https://krunker.io/) 只保留作辅助网页 FPS 对照，不能替代 CS2 标准。武器、角色、地图、美术、声音和品牌内容不复制参照资产。

- **画面与动画**：枪体和双手有清楚的前后关系；每发有短促推动和连续复位；弹匣退出、装入、闭锁可读，不能用整枪倾斜定格代替整个换弹。
- **瞄准与反馈**：中心瞄点跟随输入，枪体动画不偷偷改变弹道；开枪、命中、要害与击倒可区分，未命中不制造命中提示。
- **声音**：开火、枪械机构、换弹阶段与命中确认分层，近远和左右可辨；声音与现有玩法事件同步，不泄露未授权敌人信息。
- **界面与完成度**：弹药、换弹剩余时间和重新就绪可迅速读取；切枪、暂停、回合结束不能留下假枪口火光或重复播放旧事件。

CS2 对照必须逐项记录，而不是凭印象填数：移动与停步后的射击精度、连续开火与停止后的后坐恢复、命中与死亡的可读性、换弹阶段及打断、枪声／机构／脚步的层次与同步、界面对战场信息的遮挡。记录参照实际版本、输入和截图／录像；本作相应模块能复用的契约与工具链一并说明。没有实际玩过或听到的维度保持未验证，不自行把当前实现写成 CS2 已有行为。

同一视角和输入片段做原版／候选对照，另与参照并排截图或录像；实际玩后由非作者按上述维度列差距并复评。自动测试是回归门槛，不能据此宣布品质完成。CPU 回退和 Three.js 分开记录；参照或 GPU 无法实玩时，该项保持未验证，不降低目标。

## 第一个可玩版本

- **地图**：一张小图，一个炸弹点，三条进攻路线，包含近距离拐角和中距离对枪位。
- **武器**：一把步枪、一把手枪，有弹匣、换弹、固定后坐图案和移动射击惩罚。
- **对局**：1v1 起步，模拟层按 3v3 设计；回合计时、安放与拆除、胜负与换边。
- **操作**：鼠标锁定视角，WASD 移动，蹲伏、静步、换弹、切枪。暂停菜单提供 0.10–3.00× 鼠标倍率；1.00× 保持原版，草稿按应用保存到当前浏览器，取消不生效，恢复默认清除保存覆盖。设置不改弹道、后坐或已经记录的命令。菜单打开时 Tab／Shift+Tab 不进入背景对局控件；退出指针锁暂停后，焦点交给继续按钮。设置内 Esc 取消未应用草稿并返回设置入口；暂停菜单上的 Esc 不自动恢复游戏，继续仍由按钮确认。

### 首轮规则

回合 70 秒，安放 3 秒、拆除 5 秒、引爆 25 秒；连续 3 回合后换边，比分跟随队伍而非攻守身份。移动、开枪、换弹或切枪会打断安放／拆除，松开交互键也会清空进度。炸弹未安放时，进攻方全灭由防守方获胜；安放后即使进攻方全灭，仍须拆除或等待引爆。双方角色都会挡子弹，友伤开启。

同一时刻先完成已到期的交互，再处理引爆／回合超时；因此刚好完成的拆除优先于爆炸。开枪事件按帧内时刻排序，相同时刻按命令在输入批次中的顺序执行。

### 旁置完整训练赛候选

`?match=complete-v1` 在现有 1v1 爆破规则上提供六回合训练赛：前三回合进攻、后三回合防守，每侧恰好三回合；打满六回合后结算总比分，3:3 明确为平局，不加未经设计的突然死亡。六回合是本候选对“每三回合换边”的完整会话编排，不改变默认无限回合训练，也不改模拟规则、武器伤害、机器人难度、地图或经济。

菜单给出当前攻守职责，第三回合后说明下一回合交换身份；每回合记录攻守、胜负及胜负原因，整场结算展示本人射击命中与目标获胜次数。结束后的“再打一场”重置比分、记录和对局状态，回到部署确认，不自动锁鼠标开战。只统计本人的既有射击事实，不显示隐藏敌人的位置。该候选的浏览器、实际可读性与完整游玩验收独立进行。

## 技术默认

- **TypeScript + Vite，Three.js 渲染**；物理与角色控制用 [Rapier](https://github.com/dimforge/rapier.js) 的角色控制器和射线检测；机器人寻路用 [recast-navigation-js](https://github.com/isaac-mason/recast-navigation-js)。
- 无 WebGL2 时提供明确标识的 Canvas2D CPU 第一人称回退，读取同一地图与模拟快照；简化画面与输入单列验证，不代替 Three.js / WebGL2 验收。
- **模拟**：60 Hz 固定逻辑帧，只接受输入命令，按“种子 + 命令序列”可复现。开枪命令带帧内时间和当时的视角，命中按开枪那一刻判定，不按下一个逻辑帧。
- **瞄准**：视角在每个渲染帧直接应用累计的鼠标位移，不等逻辑帧；指针锁定时请求 `unadjustedMovement`，绕过系统鼠标加速，浏览器不支持时回退普通锁定。
- **机器人**：只对有视线的目标开火；难度靠反应时间、预瞄误差和压枪能力区分，不靠穿墙信息或伤害加成。
- 换掉任何一项，在本节写一句理由。

## 自动验收目标

`npm run sim -- --games 200 --seed 1` 应满足：

- 0 异常，0 卡死，0 次对无视线目标开火；
- 同难度机器人按攻守统计：多个种子跑满 500 局以上，进攻方胜率在 40%–60%，用来检查地图攻守平衡；
- 高难度对低难度胜率不低于 80%，反应时间分布符合难度配置；
- 同一种子下后坐图案和重放状态哈希一致；
- 输出各武器命中率、爆头率和击杀时间，作为数值修改前后的对照。

瞄准跟手程度、后坐手感、脚步方向能不能听准，进入 a1dbv TASKS“待人工验收”。

## 里程碑

1. **可玩**：1 名玩家对 1 名机器人，完整回合、安放与拆除、换边；自动和浏览器验收通过。
2. **第二次需求修改**：加一把开火方式不同的武器（如霰弹或狙击开镜），并改动一条进攻路线。按 [05 §11](https://github.com/dbvv1/a1dbv/blob/main/domains/game-dev/05-gameplay-architecture.md#11-给-ai-第二次修改的最小契约) 记下改动范围、资源返工以及回放与数据兼容。
3. **扩展**：3v3、经济系统、第二个炸弹点，在第 2 步完成后再定。

## 不做

联网对战、匹配排位、皮肤、反作弊。
