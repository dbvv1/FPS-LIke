# 手感规格与 CPU 基线

## ground-v1 地板接触位移分离（2026-10-30）

基于已接收摩擦修复 `dfdcc47`，不修改该轮摩擦／加速度公式。真实控制器探针复现：三个合法出生点的走／蹲中有13次明显水平位移损失，均命中整块地板collider0，法线约(0,1,0)。历史72356e28探针中，原出生点步行tick12的持续向下贴地的斜向cast只返回撞地前位移，剩余水平位移未保留，Game再按实际位移反馈速度放大失速。此前单变量探针把请求y改为0可消除此现象，但不能据此全局取消下落，也没有证明WASM内部触发原因，不称Rapier已知bug。

最小方案只由ground-v1调用：有水平位移（含惯性滑行）且请求向下时，先用原向下量查询当前actor的真实支撑；已接地才执行水平cast，保留其autostep产生的实际高度，再更新位置／碰撞空间并在目的地应用原向下约束。离地、向上或纯竖直请求走原combined路径。每次重查，无跨actor grounded缓存；墙面后仍按最终真实位移回写速度。默认、movement-v2与无feel训练赛保持原路径；保留原y≥0世界边界，没有增加任意负高度地形能力。

[同脚本前后数值、接触记录及成本](quality/feel/ground-contact-fix.json)。`tools/measure-ground-stances.ts` 使用首tick命令、后续空step；三个位置×run/walk/crouch×前向/对角均实测，60tick末速与声明目标差小于0.02，明显接触吞位移记录13→0。不是只核纯函数：

|---|---|---:|
| (0,0,-16) | 跑／走／蹲 | 4.500845→4.499941／2.138886→2.300002／1.697655→1.700001 |
| (0,0,-12) | 跑／走／蹲 | 4.500016→4.499999／1.653398→2.299954／1.309448→1.700000 |
| (8,0,-12) | 跑／走／蹲 | 4.500786→4.492362／1.916382→2.300000／0.156317→1.699997 |

原三模型`measure-feel`前9项完整记录逐字段相同。ground跑步公式未调；本次物理路径修正后真实滑停仍350ms、反向首次非正仍116.67ms，滑停距离0.608700。物理测量改变不等于标杆改善，可靠标杆和屏幕反馈仍待测。

完整368项CPU测试及类型检查通过，默认10局模拟无异常／停滞，ground九机器人六回合双次完整回放相同。新增回归包含站／蹲跨0.2m台阶、0.4m高阶阻挡、下台阶落回地面、向上离地后持续下降、贴墙滑动和转向无蓄速、两个actor地面／空中交错、逐tick快照／hash回放。既有真实死亡、下一回合重置及滑行装拆门槛仍通过。台阶是测试夹具，没有改变游戏地图或添加玩法。

代价：已接地水平运动最多由1次cast/1次world.step增至3次cast/2次step；当前世界只有固定collider和sensor，不含动态刚体。`tools/measure-ground-contact-cost.ts` 对10个实际移动actor测180tick，预热后5次交错前后运行，仅计Game.step、排除快照克隆／渲染：总耗时中位70.60→138.95ms，单步中位0.333→0.678ms，约两倍；候选各轮p95为1.164–1.476ms。这仅是本云CPU样本，不能推断所有设备或整帧性能。

生产四路真实重开与灯光组合的结果以本候选冻结构建的实际回执为准；CPU测试不替代浏览器、手感或完整场景性能。

## ground-v1 低速摩擦死区修正（2026-10-30）

从已发布72356e28复现真实缺陷，不是CS2标杆实测结论。原蹲走每tick加速 `5.5×1.7/60=0.155833` 小于固定最低摩擦 `5.2×2.032/60=0.176107`，上一帧速度每次被清零；纯函数180tick仍停在0.155833。真实Game首tick发蹲走、随后空输入，从(0,0,-16)1秒仅前进0.145950，末速0.155834；不是输入未保持。

只修显式ground-v1的组合：有移动输入时，将最低摩擦参考速度乘 `wishSpeed/runSpeed`，保留摩擦系数、加速度系数及声明的跑/走/蹲速度；无输入仍用原停止摩擦。三姿态的归一化响应一致，低幅analog也不再受固定站立下限卡死。任意非零analog与严格零输入的摩擦不同，本作没有新增摇杆死区。姿态切换保留既有动量，不瞬间截断到新速度上限。

[同脚本前后数据](quality/feel/ground-stances-fix.json)由 `node --import tsx tools/measure-ground-stances.ts <output.json>` 生成，三个合法出生点×三姿态×前向/对角；真实Game60tick与无碰撞纯函数180tick分列，按id定位玩家。修后纯函数均达到run4.5/walk2.3/crouch1.7，斜向没有增速。原 `measure-feel.ts --ground` 的完整结果逐字段不变：566.67ms跑步起步、350ms滑停和116.67ms反向仍是本作测量，没有可靠标杆录像，不擅调。

| (0,0,-16) 跑 | 4.500845 | 4.500845 | 3.747587→3.747587 |
| (0,0,-16) 走 | 0.488713 | 2.138886 | 0.455703→1.504081 |
| (0,0,-16) 蹲 | 0.155834 | 1.697655 | 0.145950→1.197071 |

**上一轮保留缺口：控制器的地板接触损失（本次后继修复见上节）。** 只读包装实际Physics.move记录原生接触：原点步行tick12期望dz0.00987597、实际0.000493，命中地板collider0、法线约(0,1,0)；前后发生明显位移损失的记录均为地板接触。该数值问题在不同出生点/时刻出现，实际速度回写会放大其影响；上表最后一行不能因纯函数达速就写成真实稳定达速。未改共享Rapier控制器、地板或碰撞反馈，不提高加速度掩盖它。下一独立修复需核控制器接触/滑动条件并覆盖旧模型。

回归覆盖三姿态、对角、0/极小/.009/.01/半幅输入、姿态切换、松键、反向、真实蹲走、死亡和下一回合重置，以及滑行拆包仍须真实速度低于.01。安放/拆除同时要求输入长度<.01及真实速度<.01，未放宽门槛。CPU不代替屏幕延迟、人感或完整控制器修复；生产四路重开及灯光组合结果另附实际执行回执。

基线源 `83e7c0b4e2c026ded1906aa5be71601859482431`，Node 24.22.1，60 Hz；2026-10-29 实测。默认、movement-v2 和 offline-training-v1 分开计，不将旁置的运动模型写成 v15 训练赛已有能力。

## ground-v1 旁置训练赛：运动模型与渲染插值

入口：在原训练赛参数后加 `&feel=ground-v1`，例如 `/?gameplay=offline-training-v1&match=complete-v1&squads=offline-v1&environment=courtyard-v1&art=standards-v1&feel=ground-v1`。默认、原训练赛和 movement-v2 不变；本项是离线候选，未获屏幕帧、人感或标杆录像验收。

同一 `tools/measure-feel.ts` 输入脚本加 `--ground`，真实 Game 重放；旧三路 2700 tick 输出与原 baseline 逐字段一致。完整候选日志：[ground-v1.json](quality/feel/ground-v1.json)。

| 同脚本项目 | 原训练赛 | ground-v1 实测 |
|---|---|---|
| 前进1秒后的速度 | 4.497695 世界单位/s | 4.500845 世界单位/s |
| 松键后滑停采样端点／距离 | ≤16.67ms／0 | 350ms／0.612458 世界单位 |
| 反向首次前向速度非正／前移距离 | ≤16.67ms，直接倒退 | 116.67ms／0.202625 世界单位 |
| 起步首次≥4.49单位/s | 16.67ms | 566.67ms |
| 连射间隔／换弹 | 100ms／1.900s | 100ms／1.900s |

先按 `max(speed, stopspeed) × friction × dt` 减速，再沿期望方向补 `acceleration × wishspeed × dt`，上限为期望速度差。采用 friction=5.2、stopspeed=2.032世界单位/s、acceleration=5.5；保留4.5跑速及地图尺度。本作调校起点，未在CS2控制台核验，不能冒认当前CS2参数或品质达标。滑停350ms相比社区约400ms起点−12.5%；实际标杆同脚本录像仍缺，起步偏慢仍需非作者手感核验。

三种子（1–3）真实九机器人各完成六回合，逐个双次回放相等，未发现无视线射击；[完整比赛CPU记录](quality/feel/ground-v1-matches.json)，玩家席位保持idle。

碰撞后的真实位移回写速度，避免在墙内积累隐藏速度；玩家与九机器人共享模型。移动不准度改为真实速度占跑速比，≤34%不增加移动散布；滑行时禁止装拆包，停稳后才能开始，旧匀速路径保持原规则。

训练赛固定60Hz模拟；渲染只在该候选用 previous/current 位置及对手yaw按剩余tick比例插值。HUD、声音、射击和命中仍读当前模拟，玩家鼠标yaw/pitch每次渲染直接读Controls，不插值鼠标视角。重开/换回合/暂停恢复清历史；死亡/跨回合/大位移不跨状态混合。插值增加最多1个模拟tick的呈现滞后，是该常见方案的取舍，不称为输入延迟消失。CPU测试只证明采样连续和模拟不受render频率影响，真实144Hz屏幕和音画同步待测。

## 实测方法

`node --import tsx tools/measure-feel.ts docs/quality/feel/baseline.json` 经真实 `Game.create/step` 重放，不复制运动方程或改状态。固定 seed 1、合法出生点、两个无 bot 命令的角色，前进 60 tick 后松键／反向，另一路每 tick 请求射击 60 tick、停火、tick 150 换弹；各记录 300 tick；额外独立重放在末发后300ms/316.67ms请求第11发，读取真实图案计数与射击事件。射击由真实冷却拒绝多余请求，得到十发。位置差分测速度，单位为世界单位/秒；实测日志包括命令、位置、速度、视角、动作、实际射击及声音事件。声音事件不是可听音频。源码哈希与完整逐 tick 数据见 [baseline.json](quality/feel/baseline.json)；测试双次逐字段相等。

停步时间指松键后首次位移速度 <0.001 的采样端点，精度 1 tick；默认实际在命令时刻切零，不能把 16.67ms 采样端点称作硬件输入延迟。反向时间指首次前向速度非正，不是精确零交叉。4 秒后撞墙不影响前 1 秒/制动窗口。

## 管线核查（源码证据，不是延迟测量）

- `src/input/controls.ts` mousemove直接更新yaw/pitch，带视角的shoot命令排队；请求 `unadjustedMovement:true`，仅相应不支持错误回退普通Pointer Lock。实际设备raw input可用性未测。
- `src/client.ts` 每帧 `view.render(... controls.yaw, controls.pitch ...)`，鼠标视角不等逻辑tick。固定60Hz循环，滞后超过250ms暂停而非跳输入；按下/松开时间线由Controls消费，非setInterval射击。
- 默认、movement-v2、offline-training-v1客户端都是直接渲染当前state；未保留previous/current快照和alpha位置插值。模拟固定不等于144Hz平滑。**上述为原基线；ground-v1 旁置现已接入位置插值与摩擦运动，未开启该参数的旧入口保持基线。**
- v2模型有加速度、松键制动和反向制动，不是Source的stopspeed摩擦公式。默认/训练赛移动不准度看输入，不看真实速度。既有换弹动作分段不等于已验证接触和同帧反馈。

当前结论：尚未手感达标，也不能写“实测达标、未经人感”。CPU模拟实测、源码审核、屏幕帧测量和人感四类证据分开。

### Headless 功能 smoke 入口

训练旁置 URL 另加唯一 `smoke=ground-v1` 可自动运行内置固定命令带，不请求鼠标锁定或音频，也不接收外部命令或修改模拟状态。正常入口不受影响。命令带在原 client 的 `Game.step` 中与真实机器人命令一起执行，原 View/HUD 渲染：后退 60 tick、松键 30、反向 24、松键 30；通过原重开函数创建新 Game 后重复一次，再停止。`fpsClient.state().smoke` 只读提供 `pass`（0/1）、`steps`（每轮 144）、`complete` 与两轮 `{ticks,hash}`，两轮哈希应一致。

CPU 真实 client 夹具验证新旧两路径均无 pointer lock 完成两轮、九机器人参与、重开后哈希一致、结束停步及插值渲染；此入口只解决无交互功能 smoke，不构成浏览器通过、屏幕延迟实测或品质验收。

固定 `smoke=ground-v1` 的内置输入带按每次渲染回调推进一个真实 60 Hz Game 步，位置呈现取固定半步插值；433 ms 或更长的软件渲染帧不会触发正常游玩的长帧暂停，也不会按墙钟追赶跳帧。两轮仍各 144 tick，由原 restart 创建新 Game 并比较哈希。只有唯一合法 smoke 参数启用；普通游玩仍在超过 250 ms 时暂停。此模式验证加载、真实模拟与重开，不测实时帧率、输入延迟或普通长帧体验。
