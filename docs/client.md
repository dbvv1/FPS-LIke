# 第一人称客户端

当前为本地原型，不是 brief 的完整「可玩」里程碑。Three.js 主路径保留；无 WebGL2 时自动使用醒目标记的 CPU 第一人称回退。两者只读 `Game.state`，输入与机器人共用同一个 `Game.step`，没有另一套演示战斗规则。

## 接入边界

- `src/client.ts` 固定 60 Hz 推进，渲染帧即时读取鼠标视角；枪击记录输入时刻及当时视角。卡顿超过 250 ms、失焦、隐藏页面或失去鼠标锁定会暂停，不跳过输入或在后台继续战斗。
- `src/input/controls.ts` 支持原始鼠标锁定及不支持时的普通锁定；暂停、重开和下一回合清除按住状态与待发输入。步枪连射按模拟冷却时间发枪，手枪每次点击发一枪。
- Three.js 使用共享地图的盒体与程序化角色／武器。Canvas2D 按相机位置与方向投影共享地图，做逐列墙体遮挡与角色裁剪；只提供简化地面、墙面、角色与武器反馈，不表示 Three.js 视觉质量已通过。
- 模拟以 +Z 为零偏航前方、+X 为右；Three.js 在渲染边界映射 `(x,y,z) → (x,y,-z)`，相机偏航取负。地图、角色、信标与相机一起转换；鼠标和 WASD 不改变模拟约定。无 WebGL 的真实 Three 相机投影回归覆盖四个朝向、右移／右转／抬头及 Canvas 角色列的同向位置，不能替代实际 WebGL 绘制。
- HUD 显示生命、弹药、换弹、目标进度、胜负、队伍比分与换边；`运行诊断` 和只读 `window.fpsClient` 用于观察真实状态，不提供修改模拟的测试后门。
- WebAudio 合成音效遵循模拟的可听事件过滤、距离衰减与左右声像。当前没有完整声学遮挡、武器动作制作、受击方向或击杀专属反馈；不能据此称相关模块全部跑通。
- 地图、角色和音效由本项目程序生成，没有导入商业游戏资产。

## 检查命令

```sh
npm ci
npm test
npm run build
npm run smoke:headless
npm run smoke
```

`smoke` 启动保留沙箱的 Playwright Chromium，要求 WebGL2、真实输入推进、非背景像素、暂停／重开和无应用错误。安装 Playwright 浏览器后可直接运行；也可通过 `FPS_SMOKE_CHROMIUM` 指定已有 Chromium。报告与截图写入忽略跟踪的 `outputs/browser-smoke/`。该命令不会把 CPU 回退算作 WebGL 通过，也不会跳过 GPU 断言。

仅需在现有浏览器看生产产物时，可运行 `node tools/serve.mjs`：它只监听 `127.0.0.1` 随机端口并打印地址，Ctrl+C 关闭。

## 已验证与待验证

2026-10-26，生产构建在现有云 Chrome 的 `canvas2d-cpu` 后端完成真实鼠标／键盘检查：

- 鼠标锁定、转向、移动、手枪 10→9 发、换弹被切枪中断。
- Esc 暂停冻结 tick；继续没有粘键；重开恢复血量、弹匣、位置、视角和比分。
- 通过正常探头交火连续完成三个淘汰回合；第四回合玩家换为防守方、出生点反转、比分保留。
- 导航离开后 Back 返回仍暂停且 tick 不变，继续后输入与画面恢复。
- CPU 场景与 HUD 截图可见；观察到的控制台错误仅来自浏览器扩展的 metadata 发送，不是本应用。

这不是自动 WebGL smoke：独立 Chromium 启动被环境限制阻断，现有云 Chrome 的 WebGL2 不可用；未更改浏览器安全设置。Three.js 画面、软件 WebGL smoke、长时帧时间和输入延迟均未验证。合成音效在本轮 UI 检查中关闭，声音方向与主观手感仍待人工验收。

同日追加正常入口的目标操作检查，使用现有 easy 机器人、默认规则与真实鼠标键盘，没有状态注入或数值调整：

- 玩家从进攻方走东路，靠近目标后按住 E 完成安放；tick 691 时生命 72，HUD 显示引爆倒计时 25 秒。玩家随后被击倒，回合没有错误地提前结束，机器人最终拆除并获胜。
- 重开并正常经过前三回合后，玩家换为防守方。静步绕开出生点矮箱、藏入东侧隔墙后，机器人自然安放；玩家探头瞄准并连射击倒机器人，靠近信标按住 E 5.2 秒，得到 `team: amber / reason: defuse`，比分 1:3、生命 72。
- 拆除后点击下一回合，生命／弹匣恢复 100／24，回到防守出生点、交互键清空，比分保留。CPU 高对比标识在该轮截图中清楚可见。

这只证明目标路径可由正常客户端输入完成，不代表路线平衡或新手可读性已达标。直接跑动或在长视线中静步的几次尝试仍被淘汰。攻守平衡的 63.5% / 61% 进攻胜率仍超目标，详见 [模拟层结果](simulation.md#首轮结果与下一步)。


### 暂停菜单的键盘路径

菜单沿原 DOM 改为原生 `dialog.showModal()`，借浏览器模态隔离背景；不另写 Tab 循环。打开时聚焦进入／继续或下一回合，反复显示时保有效焦点；下一回合替换主按钮或忙碌结束使原焦点失效时，才回有效主按钮。设置内 Esc 取消未提交草稿、折叠并回到原 summary；主菜单 Esc 不隐式开局。沿 [HTML dialog](https://html.spec.whatwg.org/multipage/interactive-elements.html#the-dialog-element) 的 `closedby` 关闭政策配合局部键盘处理，不能只依赖 `cancel.preventDefault()`：连续关闭请求不保证一直可取消。原锁权限及草稿检查仍由输入／设置层承担。

构建后运行 `DEBUG=pw:browser node tools/smoke-menu-focus.mjs`（默认 `/usr/bin/chromium`，可用 `FPS_SMOKE_CHROMIUM` 指定已有 Chromium）。它保沙箱、明确关闭 WebGL，用真实键盘／点击走 Tab 与反向导航、修改／取消／保存、Enter 获取指针锁、Esc 暂停和再次进入；报告与截图在 `outputs/menu-focus/candidate/`。另外检查真实菜单的 390px 窄屏和 200% CSS zoom；后者不是 OS 字号或读屏器验收。末尾合成 context-lost 事件只验错误提示不会被模态盖住，不代表 GPU 真丢失。

2026-10-26 Chromium 155 CPU 路径通过；宽屏和窄屏实图已检查，窄屏诊断入口进入正常文档流，避免压住设置脚注。键盘基线曾实际到背景画布／暂停按钮，修后不再到达；这不代表基线曾发出游戏移动／射击，也不升级为 Unity 原生 UI 证据。

`DEBUG=pw:browser node tools/smoke-menu-transition.mjs` 单独加载真实 Hud 组件，以合成回合结果和受控锁失败验证“下一回合隐藏原按钮后仍能聚焦继续”、有效设置焦点不被抢、忙碌解除后的回焦；它不是实际打完一局或 OS 拒权测试。
