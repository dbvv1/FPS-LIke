# 射击循环候选：仍在质量评估

读者是用鼠标键盘试玩中继场的玩家。
本次让同一套枪体、双手、回弹、换弹阶段、命中确认和音效共同响应真实射击事件。
采用依据是正常入口完成射击循环并与原版和公开参照并排评估；测试通过不代表品质完成。

## 改了什么

- 步枪使用一套 CC0 可编辑源网格及原创手部／机构配方，手枪保留原配方；Three 和 CPU 第一人称视图共用尺寸、姿态、换弹时钟。
- 短促后坐恢复、枪口火光、弹匣退出／装入和枪机闭锁均读取已有模拟时间，不改弹道或瞄准输入。
- 中心瞄点不漂移；外侧准星表现开火与移动，身体／要害／击倒确认只来自实际命中。落空不显示假命中。
- 弹药不足、换弹阶段、剩余时间及进度靠近弹药显示。
- 原创程序化枪声、换弹机构和命中提示替换单一提示音；敌方声音仍只消费模拟授权的可听事件。
- 指针锁定失败文字显示原生异常名与原因，不改变浏览器权限或锁定行为。

## 正常入口观察（2026-10-26）

原版为已公开的启动交付版本；候选与原版各在真实前台标签打开同一默认地图、难度和出生视角。CPU 软件画面标识保持可见。

- 两边同样 650 ms 连射到掩体，弹药均 24→17，按 R 后完成为 24/65；候选出现“退出弹匣”及剩余时间／进度，原版只有整枪倾斜及“换弹中”。
- 候选正常 D/W 绕过中央掩体；鼠标瞄准、落空、换弹、恢复后命中。画面真实显示“命中 · 28”，下一发显示“击倒确认”并正常结束回合，进攻方 1:0，玩家生命 16、弹药 20/57。
- 这次交火含多次暂停观察，不能据此声称连续对战节奏或输入延迟已达标。较早闲置观察时被机器人击倒，不计为候选操作成功。
- 前台正常入口能锁定鼠标；先前后台标签的锁定失败不再当作持续产品故障。

原始截图、输入记录和音频仅存本地观察产物，不随源码发布。参考素材同样只留本地。

## 声音边界

额外用正常按钮将同一份真实 Game 命令序列送入原版／候选 Soundscape，再经浏览器原生 OfflineAudioContext 生成各 8 秒 WAV，身体和要害命中事件一致。两份原始混音未增益，均无采样削波；原版峰值 0.1414，候选 0.2448。
原生播放器可播放不等于已听到音质。音色、方向感和音画同步的实际听感尚未评定；离线音频夹具不是用户实玩录音。

## 尚未达到的质量目标

1. 用户指定的主参照现为 CS2；尚未完成其正常射击循环实玩。Krunker 只作辅助网页比较，先前现有浏览器的 null WebGL 失败不等于本作已达标。宣传片／静帧不能替代实际比较。
2. 与原版相比枪手关系及阶段信息更清楚，但枪体屏幕占比、恢复力度、连续换弹动作和声音协调仍需非作者并排复评；落空后的环境落点反馈仍弱。
3. 隔离 Chromium 155 的 strict smoke 全部断言通过，实际 Three 画面、指针锁定、移动／瞄准／开火／换弹打断及暂停复位已观察。后续实际 argv 日志发现 Playwright 默认加入 `--enable-unsafe-swiftshader`，所以此前仅检查显式 args 的“无 unsafe”结论撤回；真实画面和输入结果保留，不证明安全启动参数或硬件性能。现脚本用 `ignoreDefaultArgs` 精确移除该默认项，安全参数以实际 argv 而非自填配置为准。

本单元仅为候选，不是品质完成或发布结论。后续依次：接收真实公开参照基线；非作者复看完整循环并选最大差距；只针对该差距调整后用同输入重评，不新增规则系统。

## 非作者质量意见后的返工候选

原候选未通过质量验收：方块枪手缺接触动作、中心大 × 遮远目标、死亡直接消失且菜单立即盖场、落空无落点。本轮针对这些差距，而不是再加规则。

- 可编辑枪手改为倒角掌／指与握把；支撑手实际到弹匣、随退出／插入路径移动再回握持位，换弹时把整段动作保持屏内。两后端仍共用几何和动作配方。
- 确认标记改为中心留空四短线，去掉身体伤害数字；静音立即停止已有音源。
- 既有权威射线附带射击当刻眼位、终点、碰撞类别及当刻致死事实；世界落点只画真实碰撞，无碰撞射线不画假火花，落点受墙体遮挡。
- 受击及死亡是表现，不延长生命／碰撞／回合；结算已发生后保留 700 ms 场景反应，再显示整轮菜单。暂停中的世界反馈仍冻结，只有已结算回合有短表现尾段。
- 新观察字段不参与 v1 玩法哈希；旧命令带逐帧哈希必须相同，旧快照没有观察字段时不猜弹痕。当前没有导入旧存档的接口，不静默添加迁移。

正常 Three 入口已观察到屏内手—弹匣接触、真实墙面落点、中心留空的身体命中标记，以及四发实际身体命中后短倒下、再显示回合菜单。11:15 UTC 按精确排除默认 unsafe 项的配置完成同一正常输入循环，实际 argv 已核无 unsafe SwiftShader／no-sandbox，站点错误为空、浏览器退出 0；保留 Chromium 原生软件回退弃用警告，不按警告加回 unsafe。此复测不回溯改写旧 strict 的启动条件，也不证明硬件性能或 CS2 品质完成。

先前录像在旧候选第一次开火时浏览器页崩溃，新候选尚未运行；未把它归因于本轮修改，失败产物保留。新对照采用正常输入静帧，不用它声称已经评完连续动作节奏。

非作者另发现 CPU 侧面看目标会变成零宽平面的回归；已把轮廓横向改为相机 right，四正交等宽、原墙体遮挡及快照不变回归通过。当前参考版本实玩、声音听感和连续动作节奏仍待补，不能拿这些代码门槛代替。

非作者亲看新旧正常输入图后接受上述可见增量，不接受 CS2 品质完成。最大剩余差距依次是：枪手仍为粗大棱柱、近端块体占屏且连续接触不够自然；敌人剪影和场景仍灰盒、远目标层次弱；落点偏小、受击不易读，死亡整身倾倒仍缺成熟动作层次。下一轮优先沿这三项改资源与表现，不另加规则系统。

## 单步枪资源与接触增量

已从官方 CC0 Quaternius Ultimate Guns Pack 选取一把步枪，原 OBJ/MTL、来源与许可、确定性导出及原创手部配方见 `assets/weapons/README.md`；不是复制 CS2 资产。两后端实际消费同一网格，不以资源面数或许可替代画面验收。

第一轮正常 Three 图中，导轨、机匣和枪托比旧棱柱有更清楚的步枪轮廓，但换弹抓握关系难读。最初把单帧读成“空抓／大间隙”的定位过于确定：弹匣离开枪身本来就是正常动作，不能据此证明手离开了弹匣；首轮证据保留，不以误读宣称修复。随后改为从原弹匣实际侧面导出握持锚点，掌面贴合并随弹匣退出／插入，另保留原创小机构件的闭锁位移。

非作者复核源码及正常输入的抓握、退出、插入、复位、就绪五阶段实图后，接收为有证据的资源／接触中间改善：真实弹匣侧下段贴掌，整组退出和回插可辨，枪体结构收益保留；独立 CPU 回退实图也消费同一网格。截图前后记录实际换弹进度区间，不把静帧当作连续动作或听感验收。

两次本轮正常输入循环分别确认 Three WebGL2 与标记清楚的 Canvas2D、完整换弹、四次实际命中和正常回合结束，无页面错误。Three 保留 sandbox，精确排除默认 unsafe 参数并核实际 argv；CPU 仅在单独隔离测试进程禁用 WebGL，不改变生产或严格 WebGL 门槛。原生软件回退弃用警告仍保留；不据此声称硬件性能或新的全量 strict 结果。

最大剩余缺口仍是手指／腕臂硬直、整臂平移而非自然接力，其次是材质和场景层次；当前 CS2 正常循环基线、连续节奏及实际听感仍未完成。本次不改模拟、伤害、时序、弹道、角色碰撞或手枪，不扩新武器玩法。
