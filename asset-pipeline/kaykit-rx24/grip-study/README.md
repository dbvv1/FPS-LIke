# Knight / RX24 原尺度握持制作视图

这是 CPU DCC 制作视图，不是游戏截图、WebGL2 验收或品质评分。制作目的：把原数值接触候选变成可直接检查的几何装配，避免把“两点对齐”当成角色真正握住枪。

## 源与做法

- 固定 Knight / Med_CombatRanged 来源与许可沿上级目录及 `docs/skinned-character-consumer.md`。源 SHA256 见 manifest；RX24 使用上级已验收 `weapon-only.glb`，未重新造枪。
- Three 0.186.1 的真实 `KayKitSkinnedCharacter` 在 `native-aim-two-hand` 末帧采样，逐顶点 `applyBoneTransform` 后应用 `matrixWorld`，导出 4276 个角色顶点；RX24 保留 5874 个源顶点。没有缩放、删改手臂或重新选取掌面。
- Blender 4.3.2 / Cycles CPU、24 samples、无降噪，1200×1000正交相机；Three `(x,y,z)` 仅变换为 Blender `(x,-z,y)`。所有色彩是制作粘土材质，不是源贴图。原PNG转为JPEG供阅读，几何源保留在 `.blend`。
- 红点为原算法“距手槽最近的主要手骨权重三角形表面”；蓝点为源手槽。它们不是已确认的解剖学掌面。rigid 图另有一个红点标出枪支撑锚。
- rigid 只把枪主掌锚平移到右手表面点，再把枪两掌锚向量旋转到角色两手点方向，缩放恒为1；完整刚体变换在 manifest。枪支撑锚与左掌候选仍差0.291502m。该假设没有用于游戏。

## 看哪张

- `palms-front.jpg`：未经装配的真实角色瞄准末帧。
- `rigid-threequarter.jpg` / `rigid-side.jpg`：原尺寸刚体候选的可读性与接触。
- `rigid-top.jpg`：只隐藏身体和头部以解除遮挡，双臂与枪几何未改。
- `knight-rx24-study.blend`：可编辑的完整粘土几何制作场景，打开即可换角度看；它是采样后静态几何，不包含可重用动画绑定。

## 制作结论

这组刚体候选不接入 View。实际图中主手与枪柄没有形成明确握持，支撑拳在前护木之外，枪管贴近拳底；只改变整体滚转或扩大枪身都不能证明接触成立。原“最近手槽表面”只是便于计算的候选，不应直接拿来定义握点。

下一方案必须先明确主手掌腔与枪柄的接触框架、左手前护木的接触面；保留现有第一人称 RX24，不把已有源动画当成已完成的持枪角色。可在本制作场景中先试真实接触框架，或选带匹配武器与动作的角色供给；未经实际制作图证明前不新增运行时 IK，也不改默认。


### 下一次可执行的接入试作

1. 在上述制作场景保留原尺度，选右掌内侧握柄面和手指围合方向，构造完整主手坐标框：掌面位置、枪柄向下、枪背向上、枪轴向前。不要继续以左右手两个点的最短旋转决定滚转。
2. 把RX24主握点固定到该右手框，只调整刚体位姿，不改枪或角色尺度；从侧/顶检查枪托与右前臂间隙。
3. 记录左肩/肘/腕的原骨长，计算原前护木目标是否在两段臂长可达区间。可达时，仅在离线DCC副本对左臂做程序两骨姿态试作，并保持手腕接触面方向；先出制作图再考虑烘焙动作，不新增运行时IK。
4. 对瞄准、开火峰值与换弹取枪/复握四个源时刻重看接触和穿模。若需要改变骨长或伸展到枪口才成立，放弃此配对，改用匹配武器的第三人称动作供给，第一人称RX24不受影响。

非作者已看本目录五种视角对应PNG：拒绝当前装配，指出侧视枪托进入右前臂、顶视左拳到了枪口而非前护木；建议先做完整主手挂接框，不据此否定所有动作/接触点组合。本批只获得这一几何制作决策，不增加内容覆盖或品质分。
